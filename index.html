One Identity Manager – Installation & KT Guide

This guide covers the complete setup process, including Virtual Machine access, project download, dependency installation, Angular CLI setup, module/component creation, and running the project.

Part 1 – Accessing the Virtual Machines

1. One Identity Manager Website

Website:

https://oneidentity.onelogin.com/login2

2. Login Credentials

  • Username: To be provided by Learnlike Team
  • Password: To be provided by Learnlike Team

3. Two-Step Verification

After entering the username and password:

  • You will be prompted to enter a Two-Step Verification (2FA) code.
  • The Learnlike Team will provide the 2FA code.

Part 2 – Starting and Accessing the Virtual Machines

4. Open the VM Portal

  • Open the One Identity Manager website.
  • Log in using the credentials provided by the Learnlike Team.
  • Navigate to the SkyTab portal.
  • Open the three Virtual Machines (VMs).

5. Start the Virtual Machines

  • Click the Start button located at the top-right corner.
  • Do not start the Virtual Machines manually.
  • The VMs will start automatically in the following sequence:
    1. Administrator
    2. Database (DB)
    3. Client
  • Wait until all three VMs have started successfully.

Important: Allow the VMs to start automatically in the specified sequence.

6. Access the Client VM

  • You only need to access the Client VM for development work.
  • The passwords for accessing each VM are available in the top toolbar of the VM window.
  • Log in to the Client VM using the provided credentials.

Part 3 – Downloading the Project

7. Open the GitHub Repository

Open the following GitHub repository:

https://github.com/OneIdentity/IdentityManager.Imx/tree/v92

8. Clone or Download the Source Code

  • Clone or download the latest source code from the repository.
  • If the project is downloaded as a ZIP file, extract the project files.
  • Open the extracted project folder.

Part 4 – Installing Project Dependencies

9. Open the Terminal

  • Open a terminal inside the project folder.
  • Make sure the terminal is pointing to the correct project directory.

10. Install Dependencies

Run the following command:

npm install

This installs the required dependencies for the project.

Part 5 – Angular CLI Installation

11. Install Angular CLI

Install the Angular CLI globally using:

npm install -g @angular/cli

What is Angular CLI?

Angular CLI (Command Line Interface) is an official command-line tool used to create, manage, build, and test Angular applications directly from the terminal.

Part 6 – Creating a Module

12. Create a Module Using Angular CLI

To create a new module in the QER project, use:

ng generate module module_name --project=qer

Example

ng generate module sample-module --project=qer

This command creates the new module inside the appropriate QER project folder.

Part 7 – Creating an Angular Component

13. Preview the Component Structure Using --dry-run

Before actually creating the component, use the --dry-run option to verify what Angular CLI will generate.

Use:

ng generate component component_name --project=qer --style=scss --export --prefix=ccc --skip-tests --dry-run

Example

ng generate component sample-component --project=qer --style=scss --export --prefix=ccc --skip-tests --dry-run

What does --dry-run do?

The --dry-run option runs the command as a simulation.

It displays:

  • Files that would be created
  • Folder paths
  • Module modifications

It does not actually modify the project or filesystem.

Part 8 – Create the Component

14. Create the Component After Verification

After verifying the generated file structure using --dry-run, remove the --dry-run option.

Run:

ng generate component component_name --project=qer --style=scss --export --prefix=ccc --skip-tests

Example

ng generate component sample-component --project=qer --style=scss --export --prefix=ccc --skip-tests

This command will actually create the component and its required files.

Part 9 – Angular CLI Options

15. Explanation of Angular CLI Options

Option Description
ng generate component component_name The core command, shorthand ng g c, instructing Angular CLI to create a new component folder named component_name.
--project=qer Tells the CLI to place the component specifically inside the qer application or library folder structure.
--style=scss Configures the component to use SCSS (.scss) for styling instead of regular CSS.
--export Automatically adds the new component to the exports array of its host NgModule, if applicable in the workspace setup, making it accessible to other modules.
--prefix=ccc Overrides the default project selector prefix. The component's HTML selector will start with ccc-, for example, <ccc-component-name>.
--skip-tests Prevents Angular CLI from generating a test configuration file (.spec.ts).
--dry-run Runs the command as a simulation and displays the expected file paths and module modifications without modifying the filesystem.

Part 10 – Component Files

16. Generated Component Files

After creating the component, Angular will generate the required files, such as:

sample-component/
├── sample-component.component.html
├── sample-component.component.scss
└── sample-component.component.ts

Since --skip-tests is used, the test file (.spec.ts) will not be generated.

Purpose of Each File

File Purpose
.html Used for the UI/template
.scss Used for styling
.ts Contains the component logic and methods

Part 11 – Running the Project

17. Open Three Separate Terminals

Open three separate terminals in the project environment.

Run the projects in the following order:

Terminal 1 – QBM

npm run build:watch qbm

Terminal 2 – QER

npm run build:watch qer

Terminal 3 – QER App Portal

npm run build:watch qer-app-portal
